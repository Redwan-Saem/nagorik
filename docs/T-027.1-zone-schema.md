# T-027.1 — canonical map zones

Planned owner: Swapnil (Ekanto), using the task list supplied on 22 October 2026.

`Zones` adds an integer key, unique case-insensitive external `Code`, display
`Name`, GeoJSON geometry, `RiskLevel`, and nullable `LastComputedAtUtc`.
Stable codes allow later integration with the existing string zone subscriptions.
No subscriptions or legacy records are remapped by this task.

Risk levels are Unknown, Low, Medium, High and Severe. A new record is Unknown
with no computation time; a later prediction job must explicitly set both the
computed level and timestamp. Dates are supplied in UTC by application callers.

Boundaries use standard GeoJSON Polygon/MultiPolygon geometry objects with
`[longitude, latitude]` positions. The database rejects malformed JSON, other
geometry types, absent coordinates and empty coordinate collections. These
checks do not prove ring closure, coordinate ranges or valid polygon topology;
the later geometry ingestion/write boundary must validate those before accepting
untrusted boundaries. Legacy Leaflet coordinate arrays cannot be copied directly.

The additive `AddZones` migration leaves WaterloggingRisks and ZoneMapData intact.
Rollback drops only the new Zones table (and therefore removes any new zone data).
No new map API, seed data, drainage points or visible page is part of T-027.1.

## Apply locally

After stopping the running app and backing up the SQLite database:

```powershell
dotnet ef database update --project .\Nagorik.Api.csproj
dotnet run --project .\Nagorik.Api.csproj --launch-profile http
```

The migration is tested on isolated databases; it is not automatically applied
to the normal local database by this implementation task.
